Background (from the session that started this one):
Ken asked whether J++ (a 2026 improvement to the Jacobian lens) could be an option in Tiny Mind, or a replacement if it's better. The J-lens lives in this repo as the kid-facing Thought Bubble app (app/jlens-explorer.html, app/jlens-guided.html), separate from the Tiny Mind repo (~\Tiny Mind), whose Microscope only has a logit lens and loads stories15M. J++ produces a same-shape linear map per layer, so the app runtime wouldn't change; the open question is whether it helps at 110M/15M scale, because the paper only tested 9B–284B models on tasks TinyStories can't do. Its filtering weights need a labeled dev set, and nobody has tested whether they help open-ended use with no target word, which is how kids use the app. Ken's kids' design rule: no unexplained parts, so prefer one lens to a J/J++ toggle if J++ wins.

Task:
Evaluate the J++ lens against the existing J-lens fits for stories110M and stories15M in this repo, and recommend: replace the J-lens / offer J++ as an option / not worth it.

What's already here: src/fit_lens.py, src/evaluate.py, out/lenses/{A,B,C}/, out/pins.json, out/report.md, out/nsweep/. app/stories110M.jlens holds J₄…J₈ (fp32, fit A, 1000 TinyStories prompts) and app/stories15M.jlens holds J₂…J₃. app/README.md documents the format and the swap demo. The venv .venv has torch 2.5.1+cu121 with jacobian-lens/ installed editable. GPU: RTX A4000.

J++ reference: the post is https://www.lesswrong.com/posts/nc9dHfcB22JdMzGbr (readable through the mirror https://www.greaterwrong.com/posts/nc9dHfcB22JdMzGbr). The code is https://github.com/safety-research/jpp_lens (Apache-2.0, derived from anthropics/jacobian-lens; scripts/jpp_cli.py; outputs a .pt with one map per layer). Method:

  • Per layer, run k-means (8 clusters) on a 64-dim PCA of centered, unit-normalized activations. Fit one averaged "expert Jacobian" per cluster. Combine them as Σ w_k·E_k, with weights learned by Adam (lr 0.05) on a small labeled dev set of latent-variable problems that is disjoint from the eval.
  • Compute the Jacobians with LRP stop-gradients through RMSNorm (LN rule) and SwiGLU (identity/half rules), plain gradients through attention.
  • At readout, drop tokens with no letter or digit.
  • The paper skips the first 16 positions as attention sinks. Check whether that makes sense for short TinyStories prompts.

Steps:

  1. Apply the readout filter alone to the existing J fits (no refit) and measure the effect.
  2. Refit with LRP only, then fit full J++. This needs a TinyStories dev set of narrative-anticipation items with known intermediate tokens (e.g. hide/hid before mom arrives, character names). Build it and keep it disjoint from the eval prompts and pins. Fit 110M at L4–L8, and also check L1–L3, since J++ gains are largest early. Fit all layers of 15M.
